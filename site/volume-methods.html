How Decibar handles monitor volume

Thirteen ways to change it, and why Decibar picked two.

Sound gets quieter in two places.

Decibar handles volume in two layers. Layer 1 is the monitor’s own volume, changed by DDC/CI commands sent over the display cable. Layer 2 is software volume, which lowers sound in a virtual audio driver before it leaves the Mac.

A concept drawing. Sound size roughly follows how loud it seems to your ear, and how far a monitor’s volume really drops varies by monitor.

Layer 1 changes what the monitor’s amp actually puts out, but the monitor has to support it and it can’t go below the minimum. Layer 2 works on any monitor and allows per-app volume and EQ, but it has to step into the audio path. Neither is enough alone, so Decibar uses both.

Why this problem exists.

A Mac’s built-in speakers and USB audio devices offer a volume control macOS can change directly. HDMI and DisplayPort audio is different. The digital signal goes straight to the monitor, and macOS sees no volume control. That’s why the slider in Sound settings is disabled and the volume keys show a “not available” symbol.

Thirteen methods.

1Used by Decibar

DDC/CI through IOAVService

DDC/CI is the standard that lets a computer and a monitor talk over the I2C line inside the display cable. Settings are read and written with VCP codes from the MCCS spec: 0x62 for speaker volume and 0x8D for mute. Apple silicon Macs have no public API for this, so Decibar uses a private one, IOAVService.

Pros The monitor’s amp level changes directly. Nothing enters the audio path, so sound quality, latency and multichannel audio aren’t affected, and it needs no permission or driver.

Cons The monitor has to support DDC/CI. Docks and adapters can block the signal. It can’t go below the monitor’s minimum. A private API can change with a macOS update, and each command takes tens of milliseconds.

2Not on Apple silicon

DDC/CI through IOFramebuffer I2C

The approach used on Intel Macs. The protocol matches method 1, with a different way in.

Verdict It doesn’t work on Apple silicon, and Decibar is Apple silicon only.

3Not universal

Monitor maker apps

Some makers offer a control app for their own monitors.

Verdict They vary by maker and model, and many have no Mac version. It’s not a general fix.

4Not on Mac

HDMI-CEC

A standard for TVs and AV gear to control each other over HDMI. It includes volume commands.

Verdict Macs don’t support CEC by default, and most PC monitors don’t either.

5Always works, slowly

Monitor buttons or remote

Change it yourself in the on-screen menu. This is the baseline that always works.

Verdict It’s reliable, but it’s several menus deep. This is the hassle Decibar removes.

6Not available

macOS system volume

The first thing most people try, but as above, macOS has no volume control to change on HDMI and DisplayPort outputs.

Verdict You can’t use it.

7One app only

A volume slider inside an app

Music apps, browser players and video call apps have their own volume.

Verdict It works in that app, but not system-wide, and not from the keyboard.

8No volume

Aggregate and Multi-Output Devices in Audio MIDI Setup

A built-in macOS feature that combines several devices into one.

Verdict It only combines them. The combined device gets no overall volume.

9Can’t lower sound

ScreenCaptureKit audio capture

This screen recording API can receive system audio.

Verdict It gets a copy while the original still plays, so it can’t lower anything. It also needs screen recording permission.

10Previous approach

Core Audio process taps

An API added in macOS 14.2. It intercepts an app’s sound, mutes the original output, and sends the processed sound to a private aggregate device.

Pros No driver to install. If the app crashes, the mute lifts and sound returns by itself.

Cons It needs audio capture permission, so an app meant to turn sound down looks like one asking to record it. Per-app volume needs a separate tap for each app.

11Used by Decibar

Virtual audio driver (AudioServerPlugIn)

A driver format macOS officially supports, which adds a virtual output device. Apps play to this device, and the driver processes the sound before it goes to the real one.

Pros All system sound is handled in one place. Each app can have its own gain. If the driver exposes no input device, it needs no audio capture permission.

Cons Installing takes an administrator password, and sound stops briefly during install. If the app passing sound along crashes while the driver is the output, audio can go silent, so it needs a recovery mechanism. The detour adds a little latency, and Decibar processes sound in stereo.

12Asks too much

Kernel extensions or injecting into the system audio process

Audio used to be handled by kernel extensions, or by putting code into the system audio process.

Verdict Apple is phasing out kernel extensions, and on Apple silicon they install only if you lower security settings. A volume app shouldn’t ask for that.

13Needs hardware

Switching to an output with volume control

With a USB DAC, Bluetooth or USB speakers, macOS volume works as usual. Speakers with a volume knob on the monitor’s 3.5mm output work too.

Verdict A good fix, but you have to buy gear. Decibar is for people who want to keep using their monitor’s speakers.

What Decibar actually does.

Monitor volume (method 1, free)

The slider in the app’s menu changes the monitor’s volume over DDC/CI, and so do the default shortcuts: Control-Option-Command-Up or Down Arrow, and Control-Option-Command-M to mute.

The real command on the cableFor a monitor whose maximum is 100

The six bytes of a Set VCP command. Each move of the slider calculates them the way Decibar does. The last byte is a checksum the receiver uses to catch transmission errors.

I2C traffic runs one transfer at a time, even with several monitors. While you drag the slider, only the latest value is kept and sent after the previous write finishes, so commands don’t pile up. A failed write gets up to 3 attempts, then Decibar reads back the value the monitor applied and shows it.

Some monitors only pretend to accept the mute command. The Dell S2725QC is one. On these models, Decibar mutes by setting the volume to 0 and restoring the previous value afterward. The list updates from this site, without an app update.

Software volume (method 11, free)

Turn this on in Settings to go below the monitor’s minimum. It works only when the output is HDMI or DisplayPort. With Accessibility permission, the volume keys control software volume in sixteen steps, or quarter steps with Option-Shift.

The slider is even in decibels: 100 is 0 dB (unchanged), 50 is −20 dB, 1 is about −40 dB, and 0 is silence. Ears hear loudness on a logarithmic scale, so this makes each step sound about the same size.

The volume keys don’t touch the monitor’s hardware volume. You set a ceiling with monitor volume, then make everyday changes below it with the keys.

Per-app volume and Pro features (method 11)

Per-app volume (0 to 150%) is free. The ten-band EQ, boost up to 12 dB and lowering other audio during calls are Pro. All of them use the same driver path and also work on outputs other than HDMI and DisplayPort. When sound could go over the maximum, a limiter prevents clipping.

The path sound takes

When Decibar steps in, and when it steps out

    The driver applies each app’s gain, writes the mix to a ring buffer in a shared file, and the Decibar app reads it and plays it on the real device.

    With software volume at 100% and EQ, boost, per-app volume and call ducking all off, Decibar leaves the path completely. The driver stays installed but sits idle.

    Why it works this way.

    Why DDC/CI for monitor volume

    DDC/CI is the only general way to control a monitor’s amp directly. Every other way lowers the signal before it reaches the amp, so the amp’s own noise stays. DDC/CI stays out of the audio path, so it works with nothing installed.

    We accepted the risk of a private API because there’s no alternative. The code that touches it lives in one file and loads it at runtime. If macOS changes, there’s one place to fix, and if the API disappears, the app doesn’t crash.

    Why not stop at DDC/CI

    Some monitor speakers are loud even at their minimum. At night, DDC/CI can’t reach anything between step 1 and mute. Per-app volume and EQ have to change the signal. And on a monitor without DDC/CI, software is the only way to lower sound.

    Why the volume keys control software volume

    Holding a volume key sends fast repeated input. Software volume changes smoothly with each audio buffer and doesn’t talk to the monitor. Fixing monitor volume as a ceiling also keeps all sixteen key steps in a useful range. Shortcuts and the slider still change monitor volume separately.

    Why process taps gave way to a driver

    Decibar started out on method 10, process taps. With no driver to install it was the easy route, but it had to ask for audio capture permission. It’s hard to explain why a volume app wants permission to record sound.

    What changes as apps are added
    Apps with their own volume3

    Today’s driver exposes no input device. Sound passes through Decibar, but the app never “records” it, so Decibar doesn’t ask for microphone or audio capture permission. We chose asking for an administrator password once over asking for permission to record.

    Per-app processing gets simpler too. Taps needed one tap per app. The driver just multiplies each app’s gain before the sound is mixed.

    Why not always use the driver

    Going through the driver adds a little latency and makes sound stereo. The driver reports 2048 frames of latency, about 43 ms at 48 kHz. There’s no reason to pay that with nothing to do, so it runs only when changing sound and otherwise leaves the path. Multichannel audio then passes through unchanged.

    What this choice costs.

    If the app quits suddenlyThe driver can’t play sound without the Decibar app

      Administrator password
      The driver installs in the system folder /Library/Audio/Plug-Ins/HAL, so it takes a password. The audio system restarts during install and update, and sound stops briefly.
      Risk of silence
      The driver can’t play sound without the Decibar app. So while the app uses the driver, a separate watchdog process runs beside it and returns the output to the real device if the app crashes. If the real device is unplugged, the app moves to another output.
      “Decibar” in Sound settings
      During processing, macOS shows Decibar as the output device. You choose the real output in Decibar’s menu.
      Stereo processing
      Sound is stereo during processing. If you need surround, turn off all software processing.
      Private API and distribution
      DDC/CI depends on a private API, so a macOS update could change how it behaves. The private API and system driver are why Decibar isn’t in the Mac App Store.
      Removal
      macOS has no way to run code when an app is removed. So a background task notices the app is gone and deletes the driver. Move the app to the Trash and it’s removed within a minute.
